# FLO — the house optimizer

Status: Draft · Pass 0 · Updated 2026-08-30

> What this is: the rebuild spec hub for the FLO (Forward-Looking
> Optimizer), the per-house bid optimizer in the private
> `gridworks-innovations/gridworks-flo` repo (`gridflo`). Today it runs
> in-process inside each LTN (`gridworks-scada`
> `gw_spaceheat/actors/ltn/ltn.py`, forked worker per step); moving it to
> its own service is OPS-514.

## Overview

`gridflo` builds a layered graph of storage states over a 48-hour horizon
from a cached **supergraph** (keyed by a hash of the house's physical
params), solves shortest-path (Dijkstra) against price and weather
forecasts, trims the graph, and produces a `BidRecommendation` and a
next-hour plan for the LTN. Supergraphs are generated by
`gridflo.supergraph_generator` and cached under
`~/.config/gridworks/gridflo/`.

## Invariants

- The FLO is bytes-in / bytes-out: `Flo(flo_params_bytes)` →
  `generate_recommendation(bytes)` → recommendation bytes. Callers hold no
  graph internals.
- A missing or mismatched supergraph raises `NeedsSupergraph`; it is never
  silently regenerated inside a solve.

## Glossary

- **supergraph** — the precomputed state graph for a house's physical
  parameters; hashed by params, cached, ~1–24 MB gzipped.
- **FloParamsHouse0** — the request: physical params + forecasts. Exists as
  a gwsproto named type and as `gridflo.asl.types`; sema word
  `flo.params.house0`.
- **BidRecommendation** — the response: price/quantity pairs for the LTN's
  bid.
