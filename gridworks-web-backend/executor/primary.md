# gridworks-web-backend — rebuild spec

Status: Draft · Pass 0 · Updated 2026-11-01

> Faithful-rebuild hub for gridworks-web-backend: the two services behind
> the fleet web page, the read API over the journal DB and the realtime
> gateway from the fleet broker. Read this hub, then the spoke for the
> concern being touched.

## What the repo is

Two processes from one checkout, run as systemd units (`deploy/`) on the
web-api2 box (gridworks-infra `platform-inventory.md`), both behind nginx:

- **`api/`** (`python -m api`, port 8000): the public read-only façade
  over the journal DB, read as `gw_visualizer`. Hourly rollups, channel
  readings, installation summaries and the CSV export the web-frontend
  draws from, and the stopgap price service's latest forecast
  (`gw.stopgap.price.forecast`) forwarded for the price panel from the
  route `BACKEND_PRICE_FORECAST_URL` names; the forward retires with the
  stopgap word (OPS-437).
- **`gateway/`** (`python -m gateway`, port 8100): the realtime WebSocket
  gateway, a very small part of the backend. Its one job is the live
  system graph on a house page, drawn from snapshots. One consumer on the
  fleet stream; each house's latest `layout.lite` and `snapshot.spaceheat`
  cached in memory and pushed to the browsers watching that house
  (`/realtime/{house_alias}`), with a whitewire series per zone and
  `/gateway/health`. `report.event` only stamps the house's last report
  time for health. A scada sends `layout.lite` only when its upstream
  link activates or on a `SendLayout` request, so after a gateway restart
  a house has snapshots but no layout until its scada next reconnects.

Both read their configuration from one `.env` with the `BACKEND_` prefix
(`template.env` names every variable).

## Cross-cutting invariants

- **Meaning comes from sema, not from the store or from channel names.**
  The journal DB holds facts; what a channel is comes from the layout
  word. Every message and record crosses the boundary through the
  vendored snapshot classes (`api/sema/`, `gateway/sema/`), never as
  hand-read dicts. Hard-coded channel-name strings in these services are
  the named enemy of the team rule that data analysis never slows
  production (OPS-542 is the cleanup).
- **Nothing in production depends on this repo.** It is outside the
  control plane: a house, an LTN and the market run unchanged when it is
  down. The alerter's dependence on the journal DB is the one exception,
  and OPS-545 removes it.
- **The gateway is a tap consumer.** It reads the fleet stream from the
  analytics tap broker (`hw1-tap.electricity.works`, AMQPS) as its own
  login (`web.gateway`; gridworks-infra `rmqtap/instance-README.md`
  "Broker logins"), binds `gw.#` on `ear_tx`, declares only exclusive
  queues named `web.gateway.<uuid>`, and publishes nowhere. A
  server-named `amq.gen-*` queue would fall outside the login's
  configure permission.
- **The browser contract is the sema wire form.** What the api answers
  with a word (`summaries`, `synced.readings.bundle`, `messages`, the
  weather routes) and what the gateway pushes to a browser is the word's
  `to_dict()`: PascalCase keys, `TypeName` and `Version` present, a null
  field left out. The browser parses each word through a zod schema in
  `gridworks-web-frontend/src/sema/` named by the word's local name (the
  `gw`/`gw1` prefix dropped on both sides: `api/sema_seed_request.yaml`
  `local_names`, the frontend seed likewise), every axiom a named
  refinement; `formats.ts` and `enums/` are generated by sema's
  TypeScript generator, the types are written by hand until it emits
  them. A word the journal holds at several versions is read through a
  union (`AnyHouseSummary`, `AnyWeatherForecast`), so either deploy order
  of the backend and the browser parses.
- **Nothing the scada reported cleanly is lost on the way to the
  browser.** When a served word drops a fact the scada's word had (a
  machine's node and enum version behind a state strip), the fix is a
  word that keeps it. A projection the browser needs that no word gives
  (a house's control mode across two machines) becomes a sema enum
  derived in the backend and sent as data; the browser renders, it does
  not infer. The browser decides no meaning by matching channel names;
  each remaining match is annotated with the fact it extracts and the
  layout or sema fact that replaces it ("Open").

## The readings csv and bundle

`/api/v2/installations/{id}/readings.download` (the csv) and
`/api/v2/installations/{id}/synced.readings.bundle` (the visualizer's
series) are one column or series per channel lineage: the
`reading_channels` rows joined by a shared name or a shared layout channel
Id (`api/v2/readings_units.py`). A name's rows differ in unit when a layout
changed how the quantity is expressed or a state machine's enum version
changed, so a lineage is in the unit of its newest row, the unit the house
sends now, with every older row's values converted into it (temperatures
and flows convert pairwise as affine maps on a reference unit; other units
only to themselves). A request names a lineage by any name it has had. Rows
of one lineage whose units do not reconcile refuse the request (422) rather
than mix scales; rows with telemetry Unknown are left out. Rows of one
lineage never overlap in time, so their union sorted by timestamp is one
series. Lineage by name rests on one rule the layouts keep: a name is
reused only for the same quantity, so `hp-lwt` is a temperature in every
layout that declares it.

The csv converts in Python: a bucket is the mean of its numeric readings
and the last of its states, and a state cell is the state's symbol in the
row's enum version; a state enum the snapshot does not vendor refuses the
request. The bundle converts inside its query, before TimescaleDB's
time-weighted average, so the rows of a lineage average together whatever
the window; a state row is no series, since the bundle word labels a series
with a unit vocabulary (`synced.readings.bundle` axiom 5), and states reach
the browser through `OperatingStateSequenceList`: one sequence per state
channel name, built from every state row of the house, each position
resolved to its symbol through the row's (enum, version), a change detected
on the symbol, times to the millisecond.

A row's kind is its `channel_type`, a `gw.channel.kind` value read through
the vendored enum (`readings_units.ChannelUnit.kind`): a `StateMachine`
row's unit type is the state enum and its unit the enum version; every
other row's unit type names the vocabulary of its unit. The readers pick
state rows by the kind and never by what the unit type is not.

## The house list and the summaries

The houses the api serves are the TerminalAsset rows of the journal's
`g_nodes` projection, keyed by the TA GNodeId and named by the
registry's `display_name`. A URL names a house by its alias, resolved to
the `g_nodes` row at `<alias>.ta`. A login's role
(`user_installation_roles`) keys on the same id; a null key is every
house, and an unknown role grants `Viewer`. The summaries route answers
one `gw.house.summary` per house the login may see
(`api/v2/routers/installation_summaries.py`), assembled per request and
stored nowhere: the role, the ids and display name, the house's
`layouts` row decoded at the version it was sent, its
`house_operating_status` row, the latest snapshot time within a day, and
the longest-running zone from the day's heat-call readings, and where
the scada's announced commit stands against the scada repo's main
(`ScadaCommitStanding`, `gw.commit.standing`): the backend asks GitHub's
compare once per distinct commit across the fleet, cached five minutes,
unauthenticated since the repo is public (`api/v2/commit_standing.py`;
`BACKEND_SCADA_REPO` names the repo). The browser does not compare
hashes: OnMainHead renders as a check, every other standing as the short
hash, Unknown plain. The gateway seeds its layouts from the same table at
start. No response names a
person: address and contact live in `gridworks-pii` and return to the
dashboard with OPS-600.

## Glossary

- **api** — the read façade process.
- **gateway** — the realtime process.
- **house alias** — the house word of a scada GNode alias
  (`hw1.isone.me.versant.keene.beech.scada` → `beech`), the key browsers
  subscribe by.
- **snapshot** — here `snapshot.spaceheat`, the scada's latest readings
  and states; the vendored `sema/` tree is also called a snapshot, and
  context tells them apart.

## Spokes

- [`visualizer.md`](visualizer.md): the visualizer page, one section per
  plot: what it shows, its word and its route.
- [`realtime.md`](realtime.md): the real-time page: the words it reads,
  a reading's unit from the layout, what the layout decides on the page.

Candidates: the API surface (routes and the readings and rollup queries
behind them) and the gateway (consumer, house state, browser messages).

## Open

- The API spoke, from `api/backend_api.py`.
- `api/backend_api.py:1241` multiplies spruce's `-set` values by ten
  (`#TODO: remove this hack`); whether the layout or the ops params now
  make it unnecessary.
- The web-frontend's expectations of the gateway's message types
  (`status`, `mqtt_message`, `zone_whitewire_series`) are written down
  nowhere but the two codebases.
- Routes that answer in no word: `alerts` (alert-manager's rows through a
  pydantic model), `hourly.electricity` without `dl` (positional
  `[ts, kwh, usd_per_mwh]` arrays), the gateway's envelopes, and the
  price forecast, which the browser fetches from the price service
  directly. The csv and xlsx downloads are files, outside the word layer;
  `sessions` is an OAuth2 token on purpose.
- The state seam loses the machine's identity: `operating.state.sequence`
  names a channel, and the browser picks a strip by regex on that name
  (`DefaultVisualizerPlot.tsx` `matchChannelName`). The build: a
  `gw.house.control.mode` enum (Unknown, LocalControl, Ltn, Admin)
  derived in the backend from `gw.house.operating.status` for a 013
  house and from the two machines before, sent as its own sequence; the
  bundle's state part naming the machine as the scada does (node, enum,
  enum version, symbols, times), a sema question decided spec-first;
  the browser selecting a strip by (node, enum). Built on dev against
  `tsdb_tap`.
- The browser's remaining name matches, each a fact the layout knows:
  zone ordinal and name (temps, setpoints, floor temps, heat calls,
  whitewire power), tank and depth ordinal (buffer, tank1 to tank3),
  the machine grouping for the LTN and local-control strips, the
  user-typed `^...$` selectors (`plot-configs.ts`, `HeatCallsPlot.tsx`,
  `DefaultVisualizerPlot.tsx`), the heat-call cell of the Houses card
  (`name like '%heat-call%'` in the backend, `-heat-call` stripped in the
  browser, so elm shows "zone2-bedrooms" where the layout says
  "bedrooms"), and the Status label (`<control mode> /
  <SeasonalStorageMode>`, a browser projection that moves into the next
  `gw.house.operating.status`). The zone ordinal has to be declared, not
  spelled into a name; the functional-name vocabulary (gwsproto's
  `names` as sema) is the shared fix and has its own issue.
- The house-to-bundle fact for the weather plot is a browser table
  (`gridworks-web-frontend/src/visualizer/house-weather-bundles.ts`)
  until `gw.operational.params` is journaled and the api resolves it from
  the newest params.
- The Houses card's first column is the registry's display name; its
  header reads "Alias". The green/red badge is "reported within the last
  minute", computed in the browser from `LatestSnapshotTime`.
- `reading_channels.terminal_asset_alias` becomes `about_g_node_alias`,
  nullable (decided 2026-10-15): a channel is about a GNode, and a
  station's observation or a fleet aggregate is about none. This repo
  names the column in raw SQL (`hourly_data_download`,
  `installation_summaries`, `readings_csv`, `hourly_electricity`) and in
  two models; the `terminal_asset_alias` strings in its sema types are
  the word's field and stay. One deploy window with gridworks-data, the
  journalkeeper and alerts.
- The dashboard's Parameters page opens on hard-coded defaults (DD power
  12 kW, DD RSWT 180 F, intermediate RSWT 130 F) while the house's
  `layout.lite` row has the scada's `Ha1Params`; the fix waits for what
  replaces Ha1Params.
- Each hand-written zod schema is checked both ways against the python
  codec as oracle: acceptance (every sample the codec accepts, zod
  accepts), rejection (one fault at a time, both reject) and emission
  (what the browser serializes decodes equal). A python harness running
  node from pytest; not built yet.
