# The TypeScript emitter

Status: Draft · Pass 0 · Updated 2026-10-28

> What this is: the sema emitter that writes a consumer's TypeScript
> snapshot, so the browser vendors its vocabulary the way the backend
> vendors its Python one. It starts from the hand-written zod schemas in
> `gridworks-web-frontend/src/sema/`, which are its acceptance fixture.

**▶ Do this next.** The type stage: read `spec/authoring/types.md` and
`spec/authoring/type-semantics.md`, then emit `types/<Class>.ts` and
`types/old_versions/<Class><NNN>.ts` from the seed DAG, with the
frontend's hand `types/` folder as the fixture: strictObject, formats and
enums by import, nested words, `TypeName` and `Version` literals,
axioms as named refinements. The round-trip over `samples/` is the gate.

## The bar

The emitter is done when, run against the seed request the browser
keeps, it reproduces the hand-written schemas in
`gridworks-web-frontend/src/sema/` and their tests pass unchanged, and
when a word that changes in sema reaches the browser by regenerating the
snapshot, the way `regen_sema_snapshot.sh` does for the Python consumers.

## Where it is built

On the `jm/ts` branch of sema, under the rule in
`wiki/conventions/sema-CLAUDE.md` "The TypeScript runtime is a work in
progress": the branch changes nothing under `definitions/`, and its
whole scope is accurate and stylistically correct TypeScript generation.
The generator is `src/sema/tools/ts_generation/`, a sibling of
`runtime_generation/` reading the same seed DAG and definitions. The
committed TypeScript runtime is `ts/runtime/`, regenerated by
`scripts/regenerate_runtime_ts.sh`; `ts/` is a Node 22 lane with zod,
Vitest, TypeScript and Prettier, and Prettier is the single source of
style, run after generation so a regen is zero-diff. Two pytest guards
in `tests/test_ts_generation.py` regenerate and diff against the
committed runtime and run the generated Vitest suite; both fail, naming
the fix, when the lane is not installed.

## Formats

- Every format in the closure is emitted from its schema keywords alone;
  there is no per-format template. `type` picks the zod base, then
  `minLength`/`maxLength` (`.length(n)` when equal), `pattern` as a regex
  literal with the class name in the message, `minimum`/`maximum`,
  `exclusiveMinimum`/`exclusiveMaximum`. A keyword outside the authoring
  spec's list, or on the wrong primitive, fails generation.
- One table of named refinements, `FORMAT_REFINEMENTS`, for a rule a
  format's description states that its keywords cannot: today only
  `market.slot.name`'s 300-second grid, which the Python validator also
  enforces and which stays prose in the definition (settled 2026-10-28).
- Sema's own gate is `formats.test.ts`, generated beside `formats.ts`
  from every format's `examples` and `counterexamples`. An integral
  float counterexample against an integer format (`1.0`) is a
  serialized-boundary rule JSON.parse erases, so the generated test names
  it in a comment and does not assert it. A consumer's snapshot gets
  `formats.ts` only; the snapshot ships data, not tests.
- The Python generator reads only `pattern` from the YAML and restates
  the other keywords in hand templates; bringing it to the keyword rule
  above is a follow-up on the Python side, so a YAML edit reaches both
  runtimes without a template edit.
- Acceptance, 2026-10-28: `formats.ts` generated for the eight formats
  the frontend imports replaced the hand file with the frontend's suite,
  typecheck and lint green. The generated file adds the `minLength` and
  36-character bounds the hand file had dropped.

## Enums

- One file per enum version in the closure: `enums/<Class>.ts` for the
  newest version in the DAG, `enums/old_versions/<Class><NNN>.ts` for
  every older one, each standalone (an old version lists its own values;
  it does not derive from the newest). `enums/index.ts` re-exports the
  newest versions.
- `enums/semaEnum.ts` is the generated base, the counterpart of the
  Python runtime's `gw_str_enum.py`. `semaStrEnum(values, default)`
  accepts the version's values and decodes a string it does not know to
  the schema's `default`, the forward-compatibility rule of
  `spec/authoring/enums.md`; a value that is not a string is rejected.
  `semaIntEnum(names, default)` does the same over
  `x-gridworks.value_descriptions`, so `.enum.Energized` reads as the
  Python member. Every schema keeps `.options` and exposes `.default`,
  `.enumName` and `.enumVersion`, the Python base's `values()`,
  `default()`, `enum_name()` and `enum_version()`.
- The Python runtime applies the rule in `GwStrEnum._missing_`, so the
  two runtimes agree on string enums, which are nearly all of them. The
  Python `IntEnum` has no such hook, so a Python integer-enum field
  rejects an unknown integer where TypeScript decodes it to the
  default; the TypeScript side follows the spec, and the Python
  `IntEnum` base is the follow-up (noted 2026-10-28). The same Python
  base still writes a `SymbolizedEnum` class nothing inherits or calls;
  it goes with that follow-up, on dev.
- `enums/enums.test.ts` is generated: every value parses to itself, an
  unknown value of the right primitive decodes to the default, the
  wrong primitive fails, and the default is among the values.
- Acceptance, 2026-10-28: the browser's seed request
  (`gridworks-web-frontend/sema_seed_request.yaml`, six enums over nine
  versions) generated an `enums/` folder that replaced the hand one with
  the frontend's suite, typecheck and lint green. Three hand tests that
  expected an unknown value to be rejected now expect the default, per
  the spec, and the hand `single.machine.state` axiom tests membership
  by `.options`, the twin of the Python axiom's `.values()`: an axiom
  that asks "is this a member" must not ask by parsing, since a parse
  decodes to the default. The hand `SpaceheatTelemetryName006` derived from 007 by
  exclusion; the generated file lists its own values.

## Shape

- Output per word: a zod schema and the inferred type, PascalCase wire
  names, `Sema: <schema_url>` as the only docstring, axioms as named
  refinements (`checkAxiom<n>`). Output per enum: a zod enum. Formats
  become zod refinements from `definitions/formats/`.
- The browser's snapshot folder is `src/sema/`, generated whole. A hand
  `.d.ts` in `src/sema/` is removed in the same change that emits its
  word: once a word is in the generated snapshot, the generated schema
  and its inferred type are the only TypeScript for it, and every import
  of the old interface moves to them. `LayoutLite.d.ts` goes first; the
  rest go as the backend-served words (`HouseSummary`,
  `SyncedReadingsBundle` and the others) join the snapshot.

## Open

- The ordering of this spoke against the functional-name vocabulary:
  formats and enums do not depend on it; the type stage meets it where
  the full-layout words name roles.

Settled 2026-10-28: the browser reads many versions of a word, as gjk
does; only the scada pins one, because it runs on Pis in homes. The
snapshot emits the newest version under the plain class name and every
older version in the closure as `<Class><NNN>`, the Python runtime's
rule. Generated tests come from the registry's own data (format
examples, and the samples for types) and run in sema's lane; a consumer
vendors schemas only.
