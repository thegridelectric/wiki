# semafy-experiments

Status: Draft · Pass 0 · Updated 2026-08-06 · Linear: OPS-490

**EDD: no** vocabulary/tooling build-out; verified by the pilot
experiment's instances passing `sema validate`, not a standalone
real-world experiment.

> What this is: experiment results become validated sema-typed
> instances instead of ad-hoc JSON, carried by a SMALL gw-prefixed
> vocabulary shared across experiment kinds — no per-kind words.

## The shape

- **Multi-experiment vocabulary only, gw-prefaced.** A word enters the
  registry only when it will likely serve MULTIPLE experiment kinds,
  and experiment words carry a `gw` prefix (e.g. `gw.experiment.run`,
  `gw.channel.jump.stats`). Kind-specific structure (an ads run's mode
  knobs, board constants) stays in the experiment folder's plain
  result files, described by its README — it does not coin words.
  Shared vocabulary (timestamps, channel names, units) is reused,
  never re-invented.
- **Use the words the data already has.** Experiment code SHALL pull
  facts from the sema-typed records that already carry them: board
  constants from the layout's thermistor-reader component; a channel's
  measurement semantics from `data.channel.gt` TelemetryName
  (spaceheat.telemetry.name) or `derived.channel.gt` OutputUnit
  (gw1.unit) — NOT from channel-config Unit/Exponent, which the
  spruce-unlimbo work removed. The ads-noise harness's hardcoded
  5.65 kΩ vs the schematic's 5k6 0.1% divider is the cautionary
  example.
- **Instances live in the experiment folder**, next to the README
  whose Found section they back. The README stays the canonical
  narrative; the instances are its machine-readable record. Filenames
  use the eventstore grammar: **dash-separated fields, each field
  internally LeftRightDot** (a field never contains a dash — a
  spaceheat.name subject converts its dashes to dots), ordered
  `<subject>-<condition?>-<type.name>-<version>.json`, e.g.
  `zone1.bedrooms.gw.microvolts-base.128sps.1hz-gw.channel.noise.stats-000.json`.
  Parsing is a bare split on dash; the same grammar the S3 eventstore
  keys use (`<from_alias>-<type.name>-<persisted_ms>-<source>.json`).
- **HARD RULE: no local dicts for experiment data.** Experiment data
  is stored and passed as sema-typed instances through the generated
  snapshot — never as ad-hoc local dicts — unless the human strongly
  and explicitly authorizes an exception. This is what semantic
  clarity is about: a dict has no contract, no validation, and no
  meaning beyond its author's memory.
- **Scripts consume the vendored sema snapshot.** Experiment code
  builds instances THROUGH the generated snapshot runtime
  (`src/gwexp/sema`, regenerated by `regen_sema_snapshot.sh` from the
  sibling sema checkout with `--allow-staged` — a dev-only snapshot,
  as staging words require) so schema and axioms validate at
  construction. Hand-built instance dicts are the antipattern this
  replaces. Until repo-ification brings the experiments folder its
  own python env, run emitters via `uv run --project ../sema python`.
- **Pin-by-hash for every canonical artifact a run consumes.**
  Experiment code reads the canonical artifact in place (never a
  folder copy — copies drift), records its sha256 + mtime in the
  result's provenance, and archives the exact bytes used in the
  experiment folder so the hash stays dereferenceable after deploys
  overwrite the source. The ads-noise harness's layout handling is
  the reference implementation.
- **The current state this replaces:** `results-summary.json` shapes
  invented per run — bare floats, no units, no validation
  (`experiments/2026-08-06-ads-noise/results-summary.json` is the
  live example).

## Display units

Depends on harmonize-units (OPS-489): affine metadata on gw1.units
values plus a generated `convert()`/`display()`. Until that lands, one
shared interim `display.py` at the experiments repo top (the
`convert_temp_to_f` shape from scada's
`gwsproto/conversions/temperature.py`, written from the enum
descriptions), deleted the day OPS-489 ships. Experiment words store
canonical scaled-int units where they quote fleet channels; whether
result *statistics* (a standard deviation in µV or °C) may be
`number`-typed is an open sema question below.

## Pilot

The ads-noise re-run with raw per-sample capture
(`experiments/2026-08-06-ads-noise/`) emits the first sema-typed
results. Its vocabulary sketch is the design's first concrete work.

## Vocabulary — two gw words

Settled 2026-08-06 (drafts in the pilot folder's `vocab/`; registry
entry as `staging`, publish only after a second experiment kind
exercises them):

- `gw.experiment.run` — the metadata every experiment result carries:
  `ExperimentSlug` (spaceheat.name — the KIND slug exactly as it
  appears in the logbook, e.g. `ads-noise`; the folder is
  `<date>-<slug>`), `HostGNodeAlias` (left.right.dot, pulled from the
  layout's scada GNode, never hardcoded), `StartUnixMs`/`EndUnixMs`
  (utc.milliseconds, TimeOrder axiom), optional `CodeRef`.
- `gw.channel.jump.stats` — one fleet channel over one archive
  window: window bounds, reading count, jump threshold and max-gap
  parameters, spike count, max and median consecutive-reading jump.
  Generic across quantities with NO unit declaration of its own: it
  travels with the channel's own sema object
  (`ChannelTypeName`/`ChannelVersion`, e.g. `data.channel.gt/002`
  whose TelemetryName implies the wire unit, or `derived.channel.gt`
  whose OutputUnit declares it), and every numeric field is in that
  channel's serialized units — restating units here would be the
  drift-risk the 5.65 kΩ lesson warns about. The canary view
  (per-channel daily spike counts flagged spruce's ADS corner three
  days before the 07-29 incident) is a list of these.

Kind-specific structure — an ads run's mode knobs, board constants,
per-mode channel statistics — stays in the folder's plain result
files with layout provenance, described by the README. Statistics MAY
be float-typed: the `positive.float` format is existing precedent
that formats refine `number`. The raw per-sample JSONL stays a plain
evidence file, not sema-typed.

## Gates

Sema word authoring follows the standing ritual: read
`sema/spec/primary.md` plus the registry/authoring spokes for the kind
being touched, summarize back, wait for confirmation. Anything
requiring a spec change (e.g. permitting `number` properties, if not
already allowed) is change-controlled — raise it, never fold it in.

## Open

- Whether the logbook entry format gains a pointer to the instances.

Resolved: result statistics may be float-typed (`positive.float` is
existing precedent for formats refining `number`); experiment
metadata is `gw.experiment.run`, coined fresh; channel statistics
carry NO unit vocabulary of their own — they pair with the channel's
sema object and speak its serialized units. A display-units enum
(`gw.display.unit`, units as humans read them, the codomain of
`display()`) was drafted and then withdrawn: with the pairing design
it had no consumer, and words are coined only when referenced. That
framing is parked on OPS-489 for harmonize-units to coin when
`display()` needs its codomain. Both gw words enter the registry as
**staging** and stay there until several experiment folders have
exercised them; the deeper wire-encoding-vs-unit reorganization
(retiring `gw1.unit` / `spaceheat.telemetry.name` toward something
like `gw.wire.encoding`) is likewise OPS-489 territory.

Semafied harness input: the ads-noise harness decodes the layout's
thermistor-reader record through the snapshot codec (no auto-upgrade;
001/002 records carry the electrical constants), falls back to a
legacy dict-walk for the fleet's pre-registry 000 records, and
records which path ran in its provenance. The 003 shape moves the
constants to the device type (dereferenced via AdcName) — wiring that
waits for the sema layout deploy, when `gw.nolan.layout` joins the
seed and the harness decodes the whole layout typed.

Both staging words are now exercised by TWO experiment folders:
ads-noise (bench run + archive canary datasets) and
spruce-no-cool-postmortem (analysis window + incident-window jump
stats — the spike cluster machine-readable). The
several-folders-before-publish gate is satisfied on count; promotion
timing is the human's call.

The pull path is live: repo-top `pull_readings.py` implements the
three stages — channel words from the scada's own layout.lite
emission in the S3 eventstore (decoded through the codec, upgraded
to current), values only from the journal DB (its unit column is a
drift tripwire, never believed), one validated `gw.readings`
instance plus a display CSV derived from it. The postmortem window
is pulled: 29 channels, 284,922 readings, validating OK.
